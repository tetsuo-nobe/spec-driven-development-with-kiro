# ラボ 1: Kiro 仕様駆動開発の基礎

<!--include:Header-->

## ラボの概要

このハンズオンラボでは、Kiro を使用して仕様駆動開発の手法で天気予報アプリケーションを構築する経験を積みます。まず、ラボ環境に接続し、AWS ビルダー ID を使用して認証を行います。次に、プロジェクトに関する永続的な知識を Kiro に提供するステアリングファイルを作成してから、Kiro の Feature Spec (機能スペック) ワークフローを使用して EARS 記法で要件を定義し、設計ドキュメントを生成して、実装タスクリストを作成します。ステアリングが完了したら、Kiro にタスクを実行させて、実際に機能するコードを生成します。追加のプロジェクトステアリングファイルを生成し、コンテキストプロバイダーや監視モードを使用して機能追加を行う練習をします。最後に、Bugfix Spec (バグ修正スペック) を使用して、バグの診断と修正を体系的に行います。

このラボを修了すると、あらゆる要件、設計上の決定事項、実装タスクが文書化された正式な仕様に基づいて、天気予報アプリケーションがローカルホスト上で動作するようになります。

:::alert このラボでは、AWS ビルダー ID から約 40 Kiro クレジットを消費します。実際の使用量は、Kiro とのやり取りの仕方によって異なります。開始する前に、アカウントに十分なクレジットがあることを確認してください。
:::

### 目標

このラボを修了すると、以下のことができるようになります。

- NICE DCV 経由でラボ環境に接続し、AWS ビルダー ID を使用して認証を行う。
- プロジェクト固有のステアリングファイルを作成し、追加のプロジェクトステアリングファイルを生成して、Kiro がコードベースを永続的に把握できるようにする。
- Requirements-First (要件ファースト) ワークフローを使用して、EARS 記法の要件、設計ドキュメント、実装タスクリストを含む Feature Spec (機能スペック) を作成する。
- Kiro に実装タスクを実行させ、天気予報アプリケーションのローカルホスト上での動作を確認する。
- コンテキストプロバイダーを使用してエージェントに情報を提供し、監視モードでハンクレベルレビューを行う練習をする。
- Bugfix Spec (バグ修正スペック) を作成し、現在の振る舞い、期待される振る舞い、変更されない振る舞いの分析に基づいてバグの診断と修正を行う。


### ラボ操作の注意点

このラボで使用する AWS サービスの機能は、ラボで必要なものに限定されています。このラボガイドで指定されていないサービスを使用したりアクションを実行したりすると、エラーが発生することがあります。

## タスク1: 環境設定と最初の操作

このタスクでは、ラボ環境に接続して Kiro IDE を起動し、AWS ビルダー ID を使用して認証を行います。通常、Kiro はノートパソコンやデスクトップコンピュータにインストールし、ローカル環境でバイブコーディングや仕様駆動開発を行うために使用します。しかし、このラボでは、Kiro を Amazon EC2 インスタンスにインストールします。ウェブブラウザを使用して Kiro がインストールされている Windows デスクトップにアクセスします。

### タスク 1.1: ブラウザから Kiro IDE デスクトップに接続する

このサブタスクでは、Kiro IDE がプリインストールされているリモートデスクトップ環境に接続します。

1. myClass にサインインして、ラボ一覧のページを表示します。

1. ラボ 1 のパネルで  [**起動**] をクリックしてラボ 1 のページを表示します。 

1. ラボ 1 のページの左側にある [**ラボの情報**] パネルから [**LabInstanceURL**] の値をコピーします。

1. この URL を新しいブラウザタブに貼り付けます。

   <i aria-hidden="true" class="fas fa-sticky-note" style="color:#563377"></i> **注:** 接続は公的に信頼された TLS 証明書を使用して Amazon CloudFront を介して提供されるため、ブラウザはセキュリティ警告なしで直接接続します。

1. DCV ログイン画面で、認証情報を入力します。

   - **ユーザー名**: LabInstanceURL の出力を参照します (完全な URL を使用した場合は事前に入力されています)。
   - **パスワード**: ラボパネルから [**LabPassword**] の値をコピーします。

1. デスクトップが読み込まれるまで待ちます。Kiro IDE はデスクトップのショートカットとして使用できます。

   <i aria-hidden="true" class="far fa-comment" style="color:#008296"></i> **考察:** 表示領域を最大化するには、ブラウザウィンドウ上部の DCV ツールバーを使用して全画面表示を切り替えます。全画面表示を終了するには、**ESC** キーを押すか、同じツールバーコントロールを使用します。

1. ノートパソコンと Windows デスクトップ間でクリップボードの同期を有​​効にします。

   このラボでは、これらの手順、ノートパソコン、Windows デスクトップ間でコマンドをコピーしてペーストします。ブラウザでクリップボードを共有できるようにするには、次の操作を行います。

   - 「...クリップボードにコピーされたテキストと画像を確認しようとしています」というメッセージが表示されたら、[**Allow**] を選択します。DCV セッションが、**クリップボードが同期されました**というプロンプトを表示します。
   - そのプロンプトが自動的に表示されない場合:

      - DCV セッションの上部で、クリップボード (2 つの四角形) アイコンをクリックします。

         これでプロンプトが表示されるはずです。[**Allow**] をクリックします。

      - DCV セッションが、**クリップボードが同期されました**というプロンプトを表示します。

      - [**完了**] をクリックします。

   <i aria-hidden="true" class="fas fa-sticky-note" style="color:#563377"></i> **注:** 一度権限を付与すると、ブラウザはセッションの間ずっとその権限を記憶します。ブラウザのタブを閉じたり更新したりしない限り、この手順を繰り返す必要はありません。

1. DCV セッションを初めて使用する前に、貼り付け機能の使い方を確認します。

   - **Windows** マシンからこのラボに接続する場合は、**Ctrl+V** を使用してテキストを貼り付けます。
   - **MacOS** マシンからこのラボに接続する場合は、**Command+V** ではなく、**Control+V** (実際の Control キー) を使用します。
   - 使用しているマシンの種類に関係なく、DCV セッションで貼り付けたい場所を右クリックしてコンテキストメニューを開き、[**貼り付け**] または [**テキストとして貼り付け**] を選択することもできます。

### タスク 1.2: Kiro を開いて AWS ビルダー ID を使用して接続する

1. Windows デスクトップのショートカットを使用して **Kiro** アプリケーションを起動します。

   <i aria-hidden="true" class="fas fa-sticky-note" style="color:#563377"></i> **注:** 起動したら、DCV セッション内で Kiro を全画面表示にします。

1. [**Sign in**] をクリックします。

   ブラウザのタブが開き、サインインまたはサインアップの方法を選択できます。

1. [**AWS Builder ID**] を選択します。

   ブラウザに [**Get started**] フォームが表示されます。

   <i aria-hidden="true" class="fas fa-exclamation-triangle" style="color:#DF2A5D"></i> **警告:** 既に AWS ビルダー ID をお持ちの場合は、ログインして使用できます。ただし、既存の AWS ビルダー ID で Kiro を以前に使用したことがある場合は、利用可能な Kiro クレジットの一部またはすべてを使用している可能性があります。その場合、ラボ中にクレジットが不足する可能性があります。**このような状況が当てはまる場合は、新しい (2 つ目の) AWS ビルダー ID を作成することを強くお勧めします。** 作成方法は以下のとおりです。


+++既存の AWS ビルダー ID でログインするための詳細を表示するには、こちらをクリックしてください。

- AWS ビルダー ID アカウントに既に関連付けられている E メールアドレスを入力します。

- <span style="ssb_orange_oval">Continue</span> をクリックします。

- [**Enter your password**] ページでパスワードを入力します。

- <span style="ssb_orange_oval">Continue</span> をクリックします。

- 認証コードの入力を求められます。送信された E メールに記載されているコードを確認します。E メールの受信には 1～2 分かかることがあります。

- 認証コードを貼り付けて、<span style="ssb_orange_oval">Continue</span> をクリックします。

- パスワードを保存するように求められたら、[**Not now**] を選択します。

- Kiro IDE がデータにアクセスすることを許可するよう求められたら、<span style="ssb_orange_oval">Allow access</span> を選択します。

- ブラウザに “You can close this window” (ウィンドウを閉じることができます) というメッセージが表示されます。 ブラウザを最小化表示します。

+++

<i aria-hidden="true" class="fas fa-sticky-note" style="color:#563377"></i> **注:** サインインで 400 エラーが表示される場合は、ブラウザタブを閉じて Kiro から改めてサインインします。

### タスク 1.3: Kiro を設定してプロジェクトを開く

1. **Kiro** アプリケーションに戻ります。

   [**Import configuration**] ページが表示されます。

1. [**Next**] をクリックします。

1. お好みのテーマ (Kiro Dark または Kiro Light) を選択し、[**Continue**] をクリックします。

1. [**Set up shell**] 画面で、[**Done**] をクリックします。

   `C:\Users\student\environment` フォルダについて、"Do you trust the authors of the files in this folder?" (このフォルダ内のファイルの作成者を信頼しますか) というメッセージが表示されたポップアップウィンドウが開きます。

1. [**Trust the authors of all files in the parent folder 'student'**] の横にあるチェックボックスをオンにして、[**Yes, I trust the authors**] を選択します。

   [**Let's build**] 画面が表示されます。

   表示される通知は自動的に閉じますので、しばらくお待ちください。現時点では対応する必要はありません。

   <i aria-hidden="true" class="fas fa-sticky-note" style="color:#563377"></i> **注:** デフォルトシェルの設定を求められたら、[**Command Prompt**] を選択して続行します。

### タスク 1.4: Kiro クレジットを獲得する

このサブタスクでは、簡単なコースアンケートに回答することで、追加の Kiro クレジットを獲得します。クレジットは、サインインに使用した Kiro アカウントに適用されます。

1. 担当インストラクターがアンケートリンクを提供します。ブラウザでリンクを開き、アンケートに回答します。

1. アンケートを送信すると、獲得用 URL (`kiro.dev/redeem/<code>` の形式) が表示されます。

1. 獲得用 URL をコピーしてブラウザに貼り付けます。

1. タスク 1.2 で使用したのと同じ Kiro アカウントでサインインします。

   クレジットはアカウントに自動的に適用されます。

1. Kiro IDE に戻ります。

1. サイドバーの下部にあるチェックマーク付きの人物アイコンをクリックして、利用可能なクレジットが増えていることを確認します。

   <i aria-hidden="true" class="fas fa-sticky-note" style="color:#563377"></i> **注:** クレジットは数分以内に使用状況ダッシュボードに表示されるはずです。5 分経ってもクレジットが表示されない場合は、ブラウザの更新を試してから、担当インストラクターに伝えます。

   <i aria-hidden="true" class="fas fa-sticky-note" style="color:#563377"></i> **注:** これらのクレジットを取得することで、両方のラボのすべてのラボ実習を完了するのに十分なキャパシティーを確保できます。

<i aria-hidden="true" class="far fa-thumbs-up" style="color:#008296"></i> **タスク完了:** Kiro がインストールされている EC2 インスタンスへの接続に成功しました。また、Kiro の起動と AWS ビルダー ID による認証にも成功しました。

## タスク 2: 環境を設定してステアリングファイルを作成する

このタスクでは、開発環境を設定して、Git リポジトリを初期化し、開発ルールに関する永続的な知識を Kiro に提供するプロジェクト固有のステアリングファイルを作成します。Kiro による要件分析、設計、タスク生成のすべてが最初からプロジェクトの設定に従って行われるよう、ステアリングファイルは仕様書よりも先に設定します。

### タスク 2.1: 環境を設定する

まず、Kiro のデフォルトターミナルを設定し、Git リポジトリを作成します。

1. IDE の左上隅にある <i aria-hidden="true" class="far fa-copy"></i> **Explorer** (ファイル) アイコンを選択します。

   これにより EXPLORER ビューが開き、プロジェクト領域内のファイルを確認できます。

1. IDE のデフォルトターミナルをコマンドプロンプトに設定します。

   - IDE の左下隅にある <i aria-hidden="true" class="fa fa-cog"></i> **Manage** (歯車) アイコンをクリックし、[**Settings**] を選択します。

   - [**Search settings**] テキストボックスで `default terminal Windows` を検索します。

   - ドロップダウンメニューで、[**Terminal] > [Integrated] > [Default Profile: Windows**] を [**Command Prompt**] に設定します。

      <i aria-hidden="true" class="fas fa-sticky-note" style="color:#563377"></i> **注:** これにより、Kiro はこのラボの後半でターミナルで実行されるコマンドの結果を読み取ることができます。

   - [**Settings**] タブを閉じます。

1. プロジェクトを Git リポジトリとして初期化します。

   Kiro で [**View**] > [**Terminal**] を選択してターミナルを開きます。

   ターミナルで、次のコマンドをコピーして貼り付け、実行します。

   ```bash
   git config --global user.email "someone@example.com"
   git config --global user.name "J Doe"
   git config --global core.autocrlf false
   git init
   echo "**/node_modules/" >> .gitignore
   echo "**/node_modules/.cache/" >> .gitignore
   git add .
   git commit -m "initial commit"
   git status
   ```

   "Are you sure you want to..." というプロンプトが表示されたら、行を貼り付け、[**Do not ask me again**] ボックスをオンにして [**Paste**] をクリックします。

   <i aria-hidden="true" class="fas fa-clipboard-check" style="color:#18ab4b"></i> **予想される出力:**

   ```bash
   C:\Users\student\environment>git status
   On branch master
   nothing to commit, working tree clean
   ```

1. チャットパネルのチャット入力エリア付近にあるモデルセレクターを見つけます。[**Auto**] を選択すると、Kiro が各タスクに最適なモデルを自動的に選択します。

   <i aria-hidden="true" class="fas fa-sticky-note" style="color:#563377"></i> **注:** モデルによって、インタラクションあたりに使用される Kiro クレジットの量が異なります。このラボでは、モデルセレクターは [**Auto**] のままにしておくことをお勧めします。これにより、品質とクレジット使用量のバランスを効率よく保つことができます。

### タスク 2.2: プロジェクトガイダンス用のステアリングファイルを作成する

ステアリングファイルは、プロジェクトに関する永続的な知識を Kiro に提供するために作成するマークダウンドキュメントです。ステアリングファイルは `.kiro/steering/` フォルダ内に保存され、Kiro はインタラクションのたびに自動的に読み込みます。このサブタスクでは、Kiro が任意の技術スタック、設計思想、ランタイム設定に沿って動作するよう、プロジェクト固有のステアリングファイルを作成します。仕様書を作成する前にこのステアリングを行っておくことで、Kiro による要件分析、設計、タスク生成のすべてが、最初からプロジェクトの規約に従って行われるようになります。

1. IDE の左側にある Kiro アイコン (ゴーストアイコン) をクリックします。

1. [**AGENT STEERING & SKILLS**] セクションで、[**Generate a custom steering document or import an agent skill**] (**+** アイコン) をクリックします。

1. [**Create Steering or Import Skills - Select a method**] で、[**environment agent steering**] を選択します。

1. ステアリングドキュメントの名前を入力するよう求められたら、`project-steering` と入力して **Enter** キーを押します。

   Kiro が `.kiro/steering/` フォルダに `project-steering.md` という名前のファイルを作成し、デフォルトのプレースホルダーコンテンツが含まれた状態でエディタにこのファイルを開きます。

   ```plain
   ---
   inclusion: always
   ---
   <!------------------------------------------------------------------------------------
      Add rules to this file or a short description and have Kiro refine them for you.

      Learn about inclusion modes: https://kiro.dev/docs/steering/#inclusion-modes
   ------------------------------------------------------------------------------------->
   ```

1. ファイルの内容を以下のテキストに置き換えます。

   ```plain
   ---
   inclusion: always
   ---

   - 設計はシンプルに保つこと。
   - 目標は 20 分でプロジェクトを完成させること。
   - アプリの構築には HTML と JavaScript を使用すること。
   - キャッシュ機能やクラス、インターフェースは実装しないこと。
   - 単体テストコードは基本的なテストのみに限定すること。`node --check` が通れば、その JavaScript は有効とみなす。このプロジェクトでは、これ以上のテスト基盤は不要。
   - 都市名をウェブアプリのコード内にハードコードしたり保存したりしないこと。代わりに、ウェブアプリ UI のエンドユーザーが入力した都市名を、そのまま National Weather Service API に渡すこと。
   - Nominatim ジオコーディングを使用して CORS エラーを回避すること。
   - ウェブアプリの起動時にパスの問題が発生した場合は、ウェブアプリを起動するためのバッチスクリプトを作成すること。
   - ローカル HTTP サーバーを起動する PowerShell スクリプトを使用して、アプリを localhost:8080 で実行すること。
   ```

1. 変更内容をファイルに保存します。

   <i aria-hidden="true" class="fas fa-sticky-note" style="color:#563377"></i> **注:** Kiro は、インタラクションのたびに `.kiro/steering/` フォルダ内のすべてのステアリングファイルを自動的に読み取ります。ファイルを読み取るよう Kiro に明示的に指示する必要はありません。

<i aria-hidden="true" class="far fa-thumbs-up" style="color:#008296"></i> **タスク完了:** 環境を設定し、これ以降のあらゆる Kiro とのインタラクションの指針となるステアリングファイルを作成しました。

## タスク 3: Feature Spec (機能スペック): 要件ファーストワークフロー

このタスクでは、Kiro の仕様駆動開発ワークフローを使用して、天気予報アプリケーションの要件定義、設計の生成、実装タスクリストの作成を行います。ステアリングファイルは作成済みのため、Kiro の出力結果はプロジェクトの規約に沿ったものになります。

### タスク 3.1: 要件を定義する

:::alert このラボ全体で Kiro と連携

<i aria-hidden="true" class="fas fa-exclamation-circle" style="color:#7C5AED"></i> **注意**: このラボにおける Kiro とのすべてのやり取りに、以下のガイドラインが適用されます。

- [**Your approval is required to continue:**] プロンプトが表示されたら、[**Allow**] または [**Always allow**]を選択します。
- [**Allow to**] では [**This workspace**] または [**All workspace**] を選択します。
- Kiro がターミナルでコマンドを実行する場合は、実行が完了するまで待ってから続行します。
- Kiro がブラウザタブを開いたら、アプリケーションをテストし、エラーがあればチャットで Kiro に報告します。
- ポートが既に使用中であるという理由で、Kiro から別のポートの使用を求められた場合は、`yes` と回答します。

:::

要件を明確にすることから仕様の作成を開始します。

1. 右側の Kiro チャットパネルで、[**Spec**] をクリックします。

   <i aria-hidden="true" class="far fa-comment" style="color:#008296"></i> **考察:** 仕様とは、アプリケーション機能の構築を構造化する体系的なドキュメントです。幅広い概念を包括的な開発ロードマップに変換するための体系的な方法を提供し、同時に監視と責任を維持します。

1. [**Autopilot**] モードが選択され、モデルオプションとして [**Auto**] が選択されていることを確認します。

1. チャットボックスに、次のプロンプトを貼り付けて送信します。

   ```plain
   ユーザーが米国の都市名を入力すると、現在の気象状況を表示するシンプルな天気予報アプリを作成してください。気象情報と都市名の取得元には、公開されている政府のウェブサイトを使用してください。HTML と JavaScript を使って構築し、PowerShell スクリプトを実行して localhost:8080 で HTTP サーバーを起動することでホストしてください。
   ```


1. Kiro に変更を実行させます。

1. ブラウザで天気予報アプリケーションを更新し、都市検索をテストします。

   - 都市を検索します (「シカゴ」や「ボストン」など)。
   - すべての検索が失敗し、"City not found" (都市が見つかりません) などのエラーメッセージが表示されることを確認します。

1. 変更をコミットし、同僚による誤ったコミットをシミュレーションします。

   ```bash
   git add .
   git commit -m "updated geocoding endpoint"
   ```

   <i aria-hidden="true" class="far fa-comment" style="color:#008296"></i> **考察**: 実際のプロジェクトでは、同僚が変更をプッシュした後に、このようなバグに気付く可能性があります。Bugfix Spec (バグ修正スペック) ワークフローは、問題を体系的に診断して、根本原因を文書化し、回帰を起こさずに修正を検証するのに役立ちます。

### タスク 6.2: Bugfix Spec (バグ修正スペック) を作成する

1. Kiro パネル内の開いているチャットセッションをすべて閉じます (これにより、バグを混入させる前のセッションのコンテキストを Kiro が引き継がないようにします)。

1. Kiro チャットパネルで、[**Spec**] をクリックします。

1. バグに初めて遭遇したかのように、チャットでバグの状況を説明します。

   ```plain
   ユーザーから、天気予報アプリの都市検索が壊れているとの報告があります。入力したすべての都市でエラーまたは "Unable to reach the geocoding service" (ジオコーディングサービスに接続できません) というメッセージが返されます。このアプリは昨日まで正常に動作していました。Bugfix Spec を使用してこの問題を調査し、修正してください。
   ```

1. メッセージが表示されたら、[**Fix a Bug**] を選択し、[**Submit answer**] をクリックします。

   Kiro は **bugfix.md** ファイルを生成します。

1. 生成された `bugfix.md` を確認し、以下の 3 つのセクションがすべて含まれていることを確認します。

   - **Current Behavior (現在の振る舞い・不具合):** 現在発生している事象 (すべての都市検索が失敗する) の説明
   - **Expected Behavior (期待される振る舞い):** 起こるはずの事象 (都市が座標に変換され、天気が表示される) の説明
   - **Unchanged Behavior (変更されない振る舞い・回帰防止):** 変更してはならないもの (UI レンダリング、気温の切り替え、表の形式) の説明

   <i aria-hidden="true" class="far fa-comment" style="color:#008296"></i> **考察:** [**Unchanged Behavior**] セクションこそが、Bugfix Spec (バグ修正スペック) によるピンポイントで確実な修正を実現する鍵となります。このセクションには、修正を適用する際に壊してはならないものが明確に文書化されています。これにより、回帰が防止されます。

### タスク 6.3: 設計を生成して修正を実行する

1. **<i aria-hidden="true" class="fas fa-arrow-right"></i> Continue** ボタンをクリックし、[**Generate Design**] を選択します。

   Kiro はコードベースを調べて問題の根本原因を突き止め、以下を含む `design.md` を生成します。
   - 根本原因分析 (誤ったジオコーディング URL の特定)
   - 修正アプローチの提案

1. 根本原因分析を確認します。ジオコーディング API の URL が無効なエンドポイントを指していることを Kiro が特定できているか確認します。

1. **<i aria-hidden="true" class="fas fa-arrow-right"></i> Continue** をクリックし、[**Generate Tasks**] を選択してから、修正を実装するタスクを実行します。

1. 修正を適用したら、天気予報アプリケーションをテストします。
   - 米国の都市 (「ボストン」など) を検索し、気象データが正しく表示されることを確認します
   - 気温切り替えが問題なく動作することを確認します。
   - 予報テーブルが正しい行数でレンダリングされていることを確認します。

   <i aria-hidden="true" class="fas fa-sticky-note" style="color:#563377"></i> **注:** テスト中にエラーが発生した場合は、その内容をチャットで Kiro に共有し、再度テストする前に解決するよう依頼します。

1. 修正をコミットします。

   ```bash
   git add .
   git commit -m "bugfix: restored correct geocoding endpoint"
   ```

<i aria-hidden="true" class="far fa-thumbs-up" style="color:#008296"></i> **タスク完了:** Bugfix Spec (バグ修正スペック) を使用してバグを体系的に診断および修正し、修正が適用されていること、回帰が発生していないことの両方を確認できました。

## まとめ

次の作業を完了しました。

- NICE DCV 経由でラボ環境に接続し、AWS ビルダー ID を使用して認証を行う。

- Bugfix Spec (バグ修正スペック) を作成し、現在の振る舞い、期待される振る舞い、変更されない振る舞いの分析に基づいて都市検索のバグの診断と修正を行う。
